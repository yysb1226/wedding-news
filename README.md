# 모바일 세로형 결혼 소식지

**초대장이 아닌 결혼 소식지**입니다. 가까운 가족들만 모시고 진행하는 작은 결혼식의 소식을 지인과 친척에게 전하기 위한, 세로형 1페이지 사이트입니다. 예식장 위치, 참석 여부(RSVP), 계좌번호, 지도 기능을 의도적으로 넣지 않았습니다.

HTML/CSS/JavaScript로만 작동합니다. npm, 웹 호스팅 서버, 빌드 과정은 필요하지 않습니다. GitHub Pages에 그대로 게시할 수 있습니다.

## 파일 구성

```text
index.html             ← 이름, 날짜, 실제 사연/문구 변경
styles.css             ← 색·글꼴·레이아웃
script.js              ← 사진 대체 표시, 스크롤 효과, 공유 버튼
.nojekyll              ← GitHub Pages에서 정적 파일 그대로 게시
assets/
  favicon.svg          ← 탭 아이콘
  photos/
    README.md          ← 사진 규격 안내
    couple-01.webp     ← 직접 추가 (표지)
    couple-02.webp     ← 직접 추가 (이야기 1)
    couple-03.webp     ← 직접 추가 (이야기 2)
    couple-04.webp     ← 직접 추가 (마무리)
```

사진 4장은 개인정보 보호를 위해 배포 ZIP에 **포함하지 않았습니다**. 업로드 전까지는 사진 자리에 안내 카드가 보입니다.

## 1) 문구 수정

`index.html`을 텍스트 편집기(VS Code 등)로 열고 다음 내용을 실제 정보로 바꿔 주세요.

- **신랑 이름**, **신부 이름**: 표지와 마지막 서명에 각각 있습니다.
- **20XX. XX. XX**: 표지와 마지막 서명에 각각 있습니다.
- **사진 4장에 대응하는 이야기**: `CHAPTER 01–04`에서 실제 두 사람의 에피소드로 수정합니다.
- **`alt`**: 사진 설명을 해당 사진에 맞게 수정합니다.
- **시제**: 예식 전 공유하면 “결혼합니다/올립니다”, 예식 후 공유하면 “결혼했습니다/올렸습니다”로 통일하는 것이 자연스럽습니다.

특히 `CHAPTER 03`의 “가까운 가족들만 모시고…” 문구가 **초대 불가의 사유를 설명하고 참석이나 축의금을 요구하지 않는지** 최종 확인하세요.

## 2) 사진 추가

`assets/photos/README.md`를 참고하여 `couple-01.webp`부터 `couple-04.webp`까지 배치합니다. 사진이 보이지 않으면 **파일 이름·대소문자·확장자·폴더 위치**를 확인하세요.

사진 크롭이 마음에 들지 않으면 `index.html`의 해당 이미지에서 다음 CSS 값을 변경합니다.

```html
style="--photo-position: center 45%;"
```

예: 피사체를 위쪽에 맞춰 보여 주려면 `center 35%` 등으로 조절합니다.

## 3) 컴퓨터에서 미리 보기

터미널에서 이 프로젝트 폴더로 이동하여 다음 명령을 실행하세요.

```bash
python3 -m http.server 8000
```

웹 브라우저에서 `http://localhost:8000`을 열고, 개발자 도구(F12)의 모바일 기기 보기로 확인합니다. Python이 없어도 `index.html` 파일을 열어 대부분의 화면은 확인할 수 있습니다.

## 4) GitHub Pages로 게시 (웹 브라우저에서)

1. GitHub 로그인 → [New repository](https://github.com/new)에서 저장소를 만듭니다. 권장 이름은 `wedding-news`입니다. GitHub Free에서는 **Public**으로 만드세요.
2. 저장소의 **Add file → Upload files**를 선택합니다. ZIP을 그대로 올리지 말고, **압축을 해제한 내부의 파일과 `assets/` 폴더**를 업로드합니다. `index.html`이 반드시 저장소 최상위에 있어야 합니다. (`.nojekyll` 파일은 숨김 파일이므로 표시 여부를 확인합니다.)
3. **Commit changes**를 클릭합니다.
4. **Settings → Pages → Build and deployment** 에서 **Source: Deploy from a branch**, **Branch: main**, **Folder: /(root)** 선택 후 **Save**합니다.
5. 배포가 끝나면 `https://<GitHub사용자명>.github.io/wedding-news/`로 열립니다. 저장소 이름이 다르면 URL 마지막 부분도 달라집니다. Pages 설정의 **Visit site** 버튼에서도 확인 가능합니다.
6. 이후 파일을 수정해 `main`에 커밋하면 사이트도 다시 게시됩니다.

원한다면 저장소 이름을 `<GitHub사용자명>.github.io`로 지어 `https://<GitHub사용자명>.github.io/` 루트 주소에 게시할 수 있습니다. 이 이름을 사용하면 해당 계정의 사용자 사이트가 됩니다.

모든 리소스 경로는 상대경로(`./styles.css`, `./assets/...`)라 두 주소 형식에서 작동합니다.

## 5) 친구들에게 공유

공개 URL을 모바일 카카오톡/문자로 보냅니다. 맨 아래 **이 소식 공유하기** 버튼을 누르면 지원되는 모바일 브라우저에서는 공유 시트가 열리고, 그렇지 않으면 링크 복사를 시도합니다.

메신저 링크 미리 보기(OG 이미지)에 사진을 표시하려면, 배포 후 `index.html`의 `<head>`에 **실제 공개된 절대 URL**로 다음을 추가할 수 있습니다.

```html
<meta property="og:image" content="https://YOUR-USER.github.io/wedding-news/assets/photos/couple-01.webp">
```

위 주소는 예시입니다. `YOUR-USER`, 저장소 이름, 파일명을 **본인의 URL로 교체**해야 합니다. 일부 메신저는 이미지를 캐시하므로 바뀐 이미지가 즉시 반영되지 않을 수 있습니다. 사진이 실제로 존재하기 전에는 `og:image`를 추가하지 마세요.

## 공개 전 점검

- 실제 이름과 날짜로 교체했는가? (HTML에 남아 있는 `20XX`, `신랑 이름`, `신부 이름`을 검색)
- 휴대전화에서 직접 열어 사진 잘림·자간·한글 줄바꿈을 확인했는가?
- 초대장이 아니므로 **예식장 주소, RSVP, 계좌 안내, 오시는 길**을 실수로 넣지 않았는가?
- 사진의 **EXIF/GPS 정보**를 제거했는가? (Git에 처음 올리기 전에 확인)
- `noindex` 메타태그는 검색 엔진에 색인을 하지 말라는 **요청일 뿐**, 비밀번호 보호나 비공개를 의미하지 않습니다. GitHub Pages URL이나 사진 파일은 링크를 아는 누구든 접근할 수 있습니다.
